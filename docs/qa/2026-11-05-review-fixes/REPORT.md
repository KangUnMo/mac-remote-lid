## 수정 결과

- `install.sh`: 실행 중 앱을 강제 종료하지 않고 정상 종료를 안내하며 중단합니다. 다운로드 전과 교체 직전에 확인합니다. ZIP의 SHA-256, `personal.remotelid` 식별자, 1.1.6 버전, `RemoteLid` 실행 파일과 실행 권한, `codesign --verify --deep --strict`를 확인합니다. 같은 설치 폴더 안의 임시 폴더에 새 앱을 준비하고 다시 검증한 뒤 기존 앱을 `previous.app`으로 백업하여 교체합니다. 교체 또는 실행 요청 실패 시 복구를 시도하며, 복구 실패 시 백업과 경로를 보존합니다. 신규 설치 후 실행 요청 실패 시 새 앱을 정리합니다.
- `Source/main.swift`: 실제 화면 꺼짐의 정상 여부나 원인 단정을 제거하고 감지된 화면 자동 꺼짐 방지 요청 유무를 표시합니다. 조회 시각을 결과와 함께 메모리에 보관하여 성공·실패 결과에 표시하고 미조회와 구분합니다. 꺼진 원격 모드를 본체 깨움 상태로 설명하지 않습니다. 요청 사유는 앱이 제공한 문구이며 `Capturing`만으로 실제 캡처 대상이나 화면 상태를 확정하지 않습니다.
- 업데이트 조회와 설치에서 같은 정식 버전·다운로드 URL 검증을 사용합니다. 초안·시험판을 제외하고 정확한 ZIP 이름과 주소를 가진 후보 중 가장 높은 버전을 선택합니다. 잘못된 첫 릴리스나 첫 파일 이후의 유효 후보도 선택합니다.
- IP 주소는 인터페이스 종류를 추정하지 않고 `네트워크 (인터페이스명)`으로 표시합니다. SSH 주소 선택 방식은 유지합니다.

## 보안 정책 확인

기존 설치 스크립트는 `xattr -cr`로 모든 확장 속성을 제거했습니다. PM에게 의도를 확인하고 승인을 받아 `xattr -dr com.apple.quarantine`으로 축소했습니다. 다른 확장 속성은 보존하고 격리 제거 실패는 기존처럼 설치를 중단하지 않습니다. 이 경우 수동 실행 허용이 필요할 수 있음을 문서에 적었습니다. 실제 앱에는 xattr을 실행하지 않았으며 모의 검사에서 인수를 확인했습니다.

SHA-256은 같은 공개 릴리스의 체크섬과 비교하는 무결성 검사입니다. 로컬 서명 검사는 Apple 공증이나 배포자 신원 검증을 의미하지 않습니다. 인앱 업데이트에는 별도 격리 제거를 추가하지 않았습니다.

## 검사 중 발견한 실패와 수정

첫 설치 모의 검사에서 macOS 기본 Bash 3.2의 빈 배열과 `set -u`가 충돌하여 `SUDO[@]: unbound variable`이 발생했습니다. PM도 같은 원인을 확인했습니다. 빈 배열을 제거하고 권한 필요 여부에 따라 실행하는 `install_command` 함수로 바꾼 뒤 `/bin/bash` 기반 모의 검사 21개가 모두 통과했습니다.

PM이 `/dev/tty` 입력을 일반 stdin만으로 분리할 수 없음을 지적하여 모의 설치 프로세스를 새 세션에서 실행하도록 보완했습니다. 이후 같은 21개 검사를 다시 실행하여 모두 통과했습니다. 원격 모드 꺼짐을 명시한 렌더링 검사를 마지막으로 보강한 뒤 빌드를 다시 실행했고 확장 자체검사까지 통과했습니다. 최종 남은 검사 실패는 없습니다.
